# kotenai-zeus-client CI/CD Pipeline Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add a standard, repo-native CI/CD pipeline for `kotenai-zeus-client` so every PR and push to `main` runs the documented quality gates, and tagged releases can build/check (and optionally publish) wheels without hand-rolled steps.

**Architecture:** Mirror what this package already documents in `docs/V2/BEST_PRACTICES.md` §11 and what sibling koten-ai repos already use: **GitHub Actions** as the orchestrator, **one local entrypoint** (`make ci`) that matches CI, and a **tag-driven release** workflow (human tag only — never auto-tag / never self-award MATRIX). Offline PR gates only; lab integration stays opt-in.

**Tech Stack:**
| Layer | Tool | Why it fits this repo |
| --- | --- | --- |
| Orchestrator | GitHub Actions | Private `koten-ai/zeus_client_python`; same pattern as `Zeus`, `zeus_client`, `koten_multi_agent_golang` |
| Package / install | `pip` + `pyproject.toml` optional `dev` extras | Already setuptools + `pip install -e ".[dev]"` |
| Tests | `pytest`, `pytest-asyncio`, `pytest-cov`, `respx` | Already in `[project.optional-dependencies].dev` |
| Lint / format | `ruff` | Documented in BEST_PRACTICES + IMPLEMENTATION_GUIDE |
| Types | `mypy` (strict on public surface; incremental elsewhere) | Documented; lighter than full pyright rollout |
| Supply chain | `pip-audit` | Explicit residual **ZCP-44**; warn → then fail |
| Build / release | `build`, `twine check`, optional PyPI Trusted Publishing (OIDC) | Matches README “Build and publish” |
| Local parity | `Makefile` targets `ci`, `test`, `lint`, `typecheck`, `build` | Matches Zeus `make ci` culture |

## Current context / assumptions

### What exists today
- **Package:** `kotenai-zeus-client` **2.0.0** (`pyproject.toml`, `src/zeus_client/_version.py`).
- **Tests:** default suite collects **~239** tests under `tests/` (`unit/`, `contract/`, `conformance/`, root smoke). `tests/legacy_v1/` is excluded via `norecursedirs`. `tests/integration/` is empty scaffold.
- **Dev deps already declared:** pytest stack + `build`. **Not declared:** `ruff`, `mypy`, `pip-audit`, `twine`.
- **No** `.github/workflows/`, **no** Makefile, **no** pre-commit, **no** `[tool.ruff]` / `[tool.mypy]` config.
- **Docs already specify the pipeline** (`docs/V2/BEST_PRACTICES.md` §11):

```text
PR:     ruff → typecheck → pytest -m "not integration" → pip-audit → coverage
Nightly: pytest -m integration (lab) + optional demo_yelp smoke
Release: full pytest → build sdist/wheel → twine check → tag → publish → SBOM/notes
```

- **Sibling references:**
  - `zeus_client/.github/workflows/test.yml` — minimal pytest + cov on PR/push.
  - `Zeus/.github/workflows/ci.yml` — required merge gate; nightly e2e separate.
  - `koten_multi_agent_golang/.github/workflows/release.yml` — tag `v*` → release artifacts.

### Assumptions
1. Repo stays **private** on GitHub; Actions are enabled (or will be) for the org/repo.
2. Implementer has push rights; enabling **required status checks** may need admin.
3. **PyPI publish is optional Phase B** — human T9 / release owner decides Trusted Publishing vs manual `twine upload`. CI must always produce and check artifacts.
4. **No live Zeus/LLM in default CI** (`pins.zeus.live_smoke=false`, BLOCKED.md). Integration job is `workflow_dispatch` / schedule only and stays non-blocking.
5. **Do not** auto-merge, auto-tag `v2.0.0`, or change `claim_level` / MATRIX.
6. Coverage threshold starts **pragmatic** (measure baseline first); do not invent a high bar that fails trunk on day one.
7. `ruff` may need a short allowlist / gradual clean if the tree has pre-existing style drift — prefer **check whole tree** with a checked-in config rather than “touched files only” in CI.

### Out of scope (YAGNI)
- Jenkins / CircleCI / Buildkite
- Docker image publish for the library itself
- Cross-repo monorepo matrix (demo_yelp / sample) in PR CI (optional nightly only)
- Replacing setuptools with hatch/poetry
- Making `legacy_v1` part of default gate
- SBOM tooling beyond a simple `pip-audit` + optional `cyclonedx` later

## Proposed approach

```text
                    ┌──────────────────────────────────────┐
  PR / push main ──►│  ci.yml  (required)                  │
                    │  lint → typecheck → test+cov → build │
                    │  pip-audit (warn first)              │
                    └──────────────────────────────────────┘
                                      │
  tag vX.Y.Z ──────►│  release.yml                         │
                    │  re-run gates → twine check →        │
                    │  (optional) PyPI + GitHub Release    │
                    └──────────────────────────────────────┘
                                      │
  schedule/manual ─►│  integration.yml (non-blocking)      │
                    │  needs lab secrets if ever filled    │
                    └──────────────────────────────────────┘

  laptop ──────────► make ci   # same steps, no Actions
```

**Design choices locked for implementers:**
1. **One source of truth for commands:** Makefile (or `scripts/ci/*.sh` called by both Makefile and Actions). Prefer Makefile for Zeus cultural fit.
2. **Python matrix on PR:** `3.11` (min) + `3.12` (primary, matches sample BFF CI) on ubuntu-latest. Optional `3.13` non-blocking later.
3. **Default pytest invocation:**
   ```bash
   pytest -q -m "not integration" --cov=zeus_client --cov-report=term-missing --cov-fail-under=<BASELINE>
   ```
   Register markers in `pyproject.toml` even if few tests use them yet.
4. **pip-audit:** job with `continue-on-error: true` until ZCP-44 is closed; then flip to blocking in a follow-up one-liner.
5. **Release:** human creates tag `vX.Y.Z` matching `project.version` / `__version__`; workflow verifies match before upload.
6. **Secrets:** never commit tokens. PyPI via OIDC Trusted Publisher when ready; no long-lived `PYPI_TOKEN` in repo if OIDC is available.

### Task 3: Add `Makefile` local parity (`make ci`)

**Objective:** One laptop command that matches GitHub Actions jobs.

**Files:**
- Create: `Makefile`

**Step 1: Create Makefile**

```makefile
# Local quality gates — keep in sync with .github/workflows/ci.yml
.PHONY: help install lint format typecheck test test-integration cov build audit ci clean

PYTHON ?= python3
PIP ?= pip
COV_FAIL_UNDER ?= 75
PYTEST_FLAGS ?= -q -m "not integration"

help:
	@echo "Targets: install lint format typecheck test cov build audit ci clean"

install:
	$(PIP) install -U pip
	$(PIP) install -e ".[dev]"

lint:
	ruff check src tests
	ruff format --check src tests

format:
	ruff check --fix src tests
	ruff format src tests

typecheck:
	mypy

test:
	pytest $(PYTEST_FLAGS)

cov:
	pytest $(PYTEST_FLAGS) \
	  --cov=zeus_client \
	  --cov-report=term-missing \
	  --cov-fail-under=$(COV_FAIL_UNDER)

test-integration:
	pytest -q -m integration

build:
	rm -rf dist build *.egg-info
	$(PYTHON) -m build
	twine check dist/*

audit:
	pip-audit

ci: lint typecheck cov build
	@echo "ci OK"

clean:
	rm -rf dist build .pytest_cache .mypy_cache .ruff_cache htmlcov .coverage
```

**Step 2: Run and fix real failures**

```bash
make install
make lint      # fix or narrowly ignore in pyproject
make typecheck # fix public/domain annotations; adapters overrides already soft
make cov
make build
make ci
```

Expected: `make ci` exits 0. If ruff/mypy flood failures, **do not** disable tools — either (a) autofix with `make format` + small typed fixes, or (b) temporarily narrow `select` / mypy packages to `zeus_client.api` + `zeus_client.domain` with a TODO comment and ticket, then expand.

### Task 5: GitHub Actions PR/push workflow (`ci.yml`)

**Files:**
- Create: `.github/workflows/ci.yml`

**Step 1: Write workflow**

```yaml
# Required merge gate for kotenai-zeus-client.
# Aligns with docs/V2/BEST_PRACTICES.md §11.1 and Makefile `make ci`.
name: CI

permissions:
  contents: read

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  workflow_dispatch:

concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  PIP_DISABLE_PIP_VERSION_CHECK: "1"
  COV_FAIL_UNDER: "75"   # replace with Task 2 baseline

jobs:
  lint:
    name: ruff
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
      - name: Install dev extras
        run: |
          python -m pip install -U pip
          pip install -e ".[dev]"
      - name: Ruff check
        run: ruff check src tests
      - name: Ruff format check
        run: ruff format --check src tests

  typecheck:
    name: mypy
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
      - run: |
          python -m pip install -U pip
          pip install -e ".[dev]"
      - run: mypy

  test:
    name: pytest (py${{ matrix.python-version }})
    runs-on: ubuntu-latest
    timeout-minutes: 20
    strategy:
      fail-fast: false
      matrix:
        python-version: ["3.11", "3.12"]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
          cache: pip
      - name: Install
        run: |
          python -m pip install -U pip
          pip install -e ".[dev]"
      - name: Test + coverage
        run: |
          pytest -q -m "not integration" \
            --cov=zeus_client \
            --cov-report=term-missing \
            --cov-report=xml \
            --cov-fail-under=${{ env.COV_FAIL_UNDER }}
      - name: Upload coverage (3.12 only)
        if: matrix.python-version == '3.12'
        uses: actions/upload-artifact@v4
        with:
          name: coverage-xml
          path: coverage.xml
          if-no-files-found: ignore

  build:
    name: build · twine check
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
      - run: |
          python -m pip install -U pip
          pip install -e ".[dev]"
      - name: Version clocks match
        run: |
          set -euo pipefail
          PY_VER=$(python -c "import pathlib,re; t=pathlib.Path('pyproject.toml').read_text(); print(re.search(r'^version\s*=\s*\"([^\"]+)\"', t, re.M).group(1))")
          IMP_VER=$(python -c "from pathlib import Path; ns={}; exec(Path('src/zeus_client/_version.py').read_text(), ns); print(ns['__version__'])")
          echo "pyproject=$PY_VER _version=$IMP_VER"
          test "$PY_VER" = "$IMP_VER"
      - name: Build sdist/wheel
        run: |
          rm -rf dist build
          python -m build
          twine check dist/*
      - uses: actions/upload-artifact@v4
        with:
          name: python-dist
          path: dist/*

  audit:
    name: pip-audit (non-blocking until ZCP-44)
    runs-on: ubuntu-latest
    timeout-minutes: 15
    continue-on-error: true
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
      - run: |
          python -m pip install -U pip
          pip install -e ".[dev]"
          pip-audit
```

### Task 6: Release workflow (tag-driven, human-only tag)

**Objective:** On `v*` tags, re-run gates, verify version == tag, build artifacts, create GitHub Release notes from CHANGELOG; optional PyPI publish behind environment protection.

**Files:**
- Create: `.github/workflows/release.yml`

**Step 1: Write workflow**

```yaml
# Tag-driven release for kotenai-zeus-client.
# Usage (human only — aligns with ZCP-43 / T9):
#   1. Bump version clocks + CHANGELOG on a PR; merge to main
#   2. git tag vX.Y.Z && git push origin vX.Y.Z
#   3. This workflow builds, checks, attaches artifacts, optional PyPI
name: Release

on:
  push:
    tags: ["v*"]
  workflow_dispatch:
    inputs:
      tag:
        description: "Existing tag to release, e.g. v2.0.0"
        required: true
        type: string

permissions:
  contents: write   # GitHub Release
  # id-token: write # uncomment when enabling PyPI Trusted Publishing

concurrency:
  group: release-${{ github.ref }}
  cancel-in-progress: false

jobs:
  release:
    name: test · build · release
    runs-on: ubuntu-latest
    timeout-minutes: 30
    environment: pypi   # optional protection rules; create in repo Settings
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          ref: ${{ github.event_name == 'workflow_dispatch' && inputs.tag || github.ref }}

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip

      - name: Install
        run: |
          python -m pip install -U pip
          pip install -e ".[dev]"

      - name: Resolve tag version
        id: ver
        run: |
          set -euo pipefail
          if [ "${{ github.event_name }}" = "workflow_dispatch" ]; then
            TAG="${{ inputs.tag }}"
          else
            TAG="${GITHUB_REF_NAME}"
          fi
          case "$TAG" in
            v*) VER="${TAG#v}" ;;
            *) echo "tag must start with v"; exit 1 ;;
          esac
          PY_VER=$(python -c "import pathlib,re; t=pathlib.Path('pyproject.toml').read_text(); print(re.search(r'^version\s*=\s*\"([^\"]+)\"', t, re.M).group(1))")
          IMP_VER=$(python -c "from pathlib import Path; ns={}; exec(Path('src/zeus_client/_version.py').read_text(), ns); print(ns['__version__'])")
          echo "tag=$TAG" >> "$GITHUB_OUTPUT"
          echo "version=$VER" >> "$GITHUB_OUTPUT"
          echo "Resolved tag=$TAG pyproject=$PY_VER _version=$IMP_VER"
          test "$VER" = "$PY_VER"
          test "$VER" = "$IMP_VER"

      - name: Full offline suite
        run: |
          pytest -q -m "not integration" \
            --cov=zeus_client \
            --cov-fail-under=${COV_FAIL_UNDER:-75}

      - name: Build + twine check
        run: |
          rm -rf dist build
          python -m build
          twine check dist/*

      - name: Extract CHANGELOG section
        id: notes
        run: |
          set -euo pipefail
          VER="${{ steps.ver.outputs.version }}"
          python - <<'PY'
          import pathlib, re, os
          ver = os.environ["VER"]
          text = pathlib.Path("CHANGELOG.md").read_text()
          # ## 2.0.0 — ... through next ## or EOF
          pat = rf"(?ms)^## {re.escape(ver)}\b.*?(?=^## |\Z)"
          m = re.search(pat, text)
          body = m.group(0).strip() if m else f"Release {ver}"
          pathlib.Path("release_notes_snippet.md").write_text(body + "\n")
          print(body[:500])
          PY
        env:
          VER: ${{ steps.ver.outputs.version }}

      - name: GitHub Release + artifacts
        uses: softprops/action-gh-release@v2
        with:
          tag_name: ${{ steps.ver.outputs.tag }}
          name: ${{ steps.ver.outputs.tag }}
          body_path: release_notes_snippet.md
          files: dist/*
          fail_on_unmatched_files: true
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      # --- Optional PyPI (enable when Trusted Publisher configured) ---
      # - name: Publish to PyPI
      #   uses: pypa/gh-action-pypi-publish@release/v1
      #   with:
      #     packages-dir: dist/
```
